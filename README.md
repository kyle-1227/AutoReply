# AutoReply

面向店铺运营的商品评价回复工具，通过 Edge 侧边栏管理评价素材、回复任务和待人工清单。

**当前版本：0.4.1 · TikTok Shop 评价读取与回复生成。** 使用原生 HTML、CSS 和模块化 JavaScript，无运行依赖、开发服务器或构建步骤。支持读取马来西亚站商品评分页的未回复评价，按明确关联的商品资料组装上下文，调用 LLM 并校验结果。生成结果保存为“已生成 · 待确认”，不自动提交店铺回复；原有本机演示入口仍保留。

## 已有功能

| 功能 | 说明 |
| --- | --- |
| 评价输入 | 支持纯文字、纯附件，以及文字与图片／视频组合；可点击选择、拖拽和多文件添加 |
| 素材预览 | 图片缩略图、浏览器视频播放器、文件名与大小展示、素材移除和重新选择 |
| 任务控制 | 按读取／添加顺序逐条生成或演示，运行期间新增评价继续纳入；支持立即暂停、继续和结束 |
| 评价队列 | 当前评价单独显示正文、素材和生成回复；待处理、已生成待确认、模拟已回复与待人工分开，支持展开和筛选 |
| 待人工清单 | 通过手动标记或演示样本，将需要人工处理的评价与原因单独展示 |
| 产品资料 | 保存产品名称、可选 SKU 和资料正文，支持增删改、跨窗口同步及编辑冲突提示 |
| 页面绑定 | 开始后固定来源标签页和完整网址，切换其他标签页不改变处理目标 |
| 多窗口运行 | 同一窗口最多占用一个任务，不同窗口可运行独立任务 |
| 悬浮入口 | 挂起或关闭侧边栏后，浮标跟随本窗口当前普通网页，显示进度与待人工数量，点击返回原任务 |
| 本机恢复 | 分别保存任务、回复和表单草稿，支持手动领取保存记录及一次性旧版记录导入 |
| 店铺评价读取 | 观察来源页正常加载的评价列表，读取真实评价／商品／SKU ID、评分、正文和买家图片，支持分页和去重 |
| 上下文与校验 | 独立 Prompt 版本、按店铺和商品精确关联资料、SKU 事实入口、300 字限制与事实引用检查 |
| 真实回复生成 | 本机保存 Key，文本／图片和视频模型分别配置；复用有限重试、立即暂停及迟到结果保护 |

## 从店铺读取并生成回复

1. 在 `https://seller-my.tiktok.com/product/rating` 的商品评分页打开插件，点击“读取未回复”。插件清除其他评分、日期和关键词筛选，并通过页面现有操作查询未回复列表，不复制登录信息或重放签名请求。
2. 展开评价可核对商品、规格和平台编号，查看买家附件。重复读取不会重复入队；订单号或正文相同、评价 ID 不同的评价分别保留。
3. 打开“生成设置”，填写 API Key 和模型 ID。Key 保存在此浏览器个人资料的扩展本地存储中，页面读取脚本和任务快照不接收 Key；可以在设置里移除。根目录 `.env` 仍仅用于 Node.js 调试，不会自动进入浏览器。
4. 可选：在产品资料中同时填写店铺 ID 和商品 ID，明确关联本地资料。手填的“产品编号 / SKU”仍是内部编号，不作为平台 SKU ID。没有关联资料时，生成通用回复。
5. 点击“开始生成”。回复跟随买家语言，无法判断时默认英语；模型必须返回约定 JSON，公开回复最多 300 个 UTF-16 代码单元。合格结果与待人工决定分开保存，技术错误或输出不合格暂停任务。
6. 点击“立即暂停”停止当前读取、请求或等待；继续前重新核对来源页，已生成结果保留。最后再读取一次未回复列表，纳入运行期间新增评价。生成结果不会减少店铺的未回复数量。

默认文本／图片模型为 `anthropic/claude-haiku-5.5`，视频模型为 `minimax/minimax-m3.1-flash:free`；可在设置中显式修改，不自动切换模型。服务端结构化输出默认关闭，只有确认端点支持后再开启。本地校验始终执行，校验通过不等于每句话都有事实依据。

当前已核实 TikTok 买家图片字段；视频类型已在业务接口和请求组装中预留，遇到未核实的平台视频字段会停止读取。模型端能否访问图片地址取决于其端点与素材权限，图片／视频理解尚未完整联调。手动上传的本地文件仍用于演示和预览，暂不加入真实模型任务。

四个对接入口、精确字段、Prompt 与商品事实示例见 [评价接入约定](评价接入约定.md)。

## 安装

需要桌面版 **Microsoft Edge 142 或更新版本**。项目已在 Windows 的 Edge 155 中进行安装与交互检查。

先获取源码：

```powershell
git clone https://github.com/kyle-1227/AutoReply.git
cd AutoReply
```

也可以在本仓库点击 **Code → Download ZIP** 后解压。

1. 在 Edge 地址栏打开 `edge://extensions`。
2. 开启“开发人员模式”，选择“加载已解压的扩展”。
3. 选择项目中的 **`extension` 文件夹**，该文件夹直接包含 `manifest.json`。
4. 在扩展菜单中将 AutoReply 固定到工具栏。
5. 前往需要处理评价的普通网页，点击 AutoReply 图标打开侧边栏。

安装和运行插件无需安装 Node.js。详细操作及更新步骤见根目录 [安装说明.md](安装说明.md)。

## 开始一次演示

1. 在侧边栏点击来源页标题，展开并核对完整网址。
2. 点击“载入演示评价”，或在“添加评价”中输入文字、添加图片／视频。文字与附件至少提供一项。
3. 点击“开始演示”，任务开始占用本窗口并绑定来源页。
4. 可以继续添加评价、切换标签页，或点击“挂起”收起侧边栏。
5. 需要人工处理的评价保留在“待人工”页；所有可自动处理的评价完成后，本轮结束并释放窗口。

产品资料入口位于右上角的“添加产品资料”。演示使用固定文案；店铺读取后的生成任务使用明确关联的资料。

## 任务运行规则

| 操作或事件 | 结果 |
| --- | --- |
| 只打开插件 | 展示准备使用的来源页，尚未占用窗口 |
| 开始任务 | 固定任务 ID、来源标签页、窗口和完整网址 |
| 立即暂停 | 取消当前步骤，保留进度和窗口占用；继续时重新处理当前未完成项 |
| 挂起、原生 X、切换标签页 | 原任务保持当前状态，运行中的任务继续推进 |
| 尚未开始时挂起 | 显示“未开始”的悬浮入口，保留草稿，不启动任务或占用窗口 |
| 同窗口其他标签页重复打开 | 显示“此窗口正在使用”，可点击“返回任务页” |
| 同一完整网址刷新 | 等待来源页恢复后接续，已完成评价保留 |
| 来源换网址、关闭或移到其他窗口 | 结束任务、释放占用并保存记录 |
| 自动完成或点击“结束任务” | 释放窗口，保留已完成结果和待人工评价 |
| 完全退出浏览器或重新加载扩展 | 未完成记录等待在明确的目标页手动恢复 |

浏览器内部页面、扩展商店等受保护页面可能无法显示浮标，原任务仍保留，可通过工具栏返回。任务推进依赖浏览器、电脑和来源页保持可用。

## 数据与窗口隔离

- 评价队列、示例回复、处理记录、评价草稿和产品表单草稿按任务分别保存。
- 手动上传的图片／视频原文件仅在当前面板会话中保留，关闭后需重新选择；店铺附件保留平台地址，可能因过期或权限而无法预览，需重新读取。
- LLM 后台重新启动后，未完成生成任务恢复为暂停，避免不明确地重复发送可能计费的请求；同网址刷新期间则自动重新读取和接续。
- 产品资料库在同一浏览器个人资料内共享；保存时检查版本，避免其他窗口的旧编辑覆盖新资料。
- 不同窗口用于隔离任务。普通新窗口仍共享网站登录状态，不同店铺账号需要独立浏览器个人资料或已有隔离环境。
- 浏览器重启后，可在目标页打开插件，通过“保存的任务记录 → 恢复到此页”领取已有记录，再手动开始。

## 独立 LLM 请求模块

`extension/llm-client.js` 导出 `requestLlm`，使用原生 `fetch` 请求 OpenRouter 的 Chat Completions API。它负责一次非流式请求，不依赖 DOM、插件消息、任务或存储。评价如何组装、使用哪个模型、模型输出正文还是 JSON，均由调用方决定。

```js
import { requestLlm } from "./extension/llm-client.js";

// Node.js 调用示例；Key 从本机环境读取，不写入源码。
const response = await requestLlm({
  apiKey: process.env.OPENROUTER_API_KEY,
  model: "anthropic/claude-haiku-5.5",
  messages: [{ role: "user", content: "Reply with OK." }],
  parameters: { max_tokens: 2048 },
});
```

本机 Key 填写在项目根目录的 `.env` 中：`OPENROUTER_API_KEY=你的Key`。该文件已被 Git 忽略，不包含在插件安装包中。运行 Node.js 调试脚本时使用 `--env-file=.env` 加载，再通过 `process.env.OPENROUTER_API_KEY` 传入请求函数；浏览器扩展不会自动读取根目录的 `.env`。

| 参数 | 说明 |
| --- | --- |
| `apiKey` | 必填，由调用方传入，模块不保存 |
| `model` | 必填，调用方明确选择的模型 ID |
| `messages` | 必填，已组装好的非空消息数组，内容原样发送 |
| `parameters` | 可选，普通对象，透传模型生成参数；不能包含 `model`、`messages`、`stream` |
| `signal` | 可选，调用方提供的 `AbortSignal`，可在请求及读取响应期间取消 |
| `timeoutMs` | 可选，默认 25000 毫秒，可覆盖；这是应用时限，不是服务商上限 |

成功时返回完整的 API JSON，包含正文、模型、用量及其他字段，不提取或解析模型正文。失败时抛出异常：HTTP/API 错误附带 `status`，存在时保留 `code` 和 `retryAfter`；成功响应中的 JSON 解析错误、网络错误、取消和超时保留原生错误。网络请求或响应读取阶段的原生 `TypeError` 额外标记 `isNetworkError: true`；输入、请求构造和序列化错误不标记。此函数只发送一次请求。

需要重试和任务控制时，使用 `extension/llm-call.js` 的 `createLlmCall(request, { onStateChange })`。一次逻辑调用创建并复用一个控制器，各任务实例独立：

```js
import { createLlmCall } from "./extension/llm-call.js";

const call = createLlmCall({
  apiKey: process.env.OPENROUTER_API_KEY,
  model: "minimax/minimax-m3.1-flash:free",
  messages: [{ role: "user", content: "Reply with OK." }],
  parameters: { max_tokens: 2048 },
}, { onStateChange: state => console.log(state) });

try {
  const response = await call.start();
  // response 是完整 API JSON，由业务调用方解释。
} catch (error) {
  // 主动暂停或取消时为 AbortError；其余错误保留原始状态与原因。
}
```

| 方法 | 说明 |
| --- | --- |
| `start()` | 启动并返回结果 Promise；重复调用复用同一 Promise |
| `pause()` | 立即暂停请求或重试等待，当前 Promise 以 AbortError 结束 |
| `resume()` | 从暂停或失败重新调用，重新获得最多三次尝试；运行中复用当前 Promise |
| `cancel()` | 终止控制器并释放输入，不能再继续；已成功结果保持成功 |
| `getState()` | 返回独立状态快照，不含 Key、消息正文或请求体 |

状态为 `idle`、`requesting`、`retry_wait`、`paused`、`succeeded`、`failed`、`cancelled`。快照包含 `status`、本轮尝试次数 `attempt`、下次允许重试时间 `nextRetryAt` 和脱敏技术错误 `error`；原始错误仍通过结果 Promise 抛给调用方。状态回调异常不影响调用结果。

网络故障、超时及 408／429／500／502／503／504 最多重试两次；HTTP 200 内顶层 API 错误也按其数字错误码判断。输入错误、JSON 解析错误和其他状态直接失败。每次尝试默认超时 25 秒；两次退避为 2 秒、4 秒，各增加 0～500 毫秒随机延迟。`Retry-After` 支持秒数和 HTTP 日期，实际等待不早于服务要求，也不短于退避时间。等待超过 60 秒时停止自动重试并保留截止时间，手动继续仍须遵守该时间。

消息与生成参数在创建控制器时复制；修改输入、模型或 Key 需要新建控制器。暂停后必须显式继续，旧的 `start()` 不会启动新请求。暂停或取消会使旧执行代次失效，迟到结果不能覆盖新调用。外部 `signal` 取消是不可恢复的终止，并保留原取消原因。可继续的控制器保留外部信号订阅，不再使用时调用 `cancel()` 释放；成功和终止会移除订阅。

控制器状态只保存在当前运行会话内；任务层在后台恢复时将未完成生成置为暂停，等待手动继续。非流式请求取消后，服务端仍可能继续生成并计费，网络重试也可能产生重复费用；本机去重仅覆盖同一控制器实例。

0.4.0 已将这两个模块接入店铺评价生成，增加本机 Key 设置和按附件类型选择模型。平台视频识别、私有素材传输、本地原文件持久化与真实回复发布仍需后续接入。

0.4.0 已通过实际 Edge 扩展检查和 MiniMax 免费端点文本联调。0.4.1 修复了未开始时挂起没有浮标的问题，目前保留 46 项回归测试。已重新检查未开始时挂起、拖动、点击恢复、跨标签页移动和运行中挂起后的任务完成。BitBrowser 真实店铺页只读识别通过，完整扩展安装与平台视频尚未验收。历史联调结果与本轮检查范围见 [验收记录](验收记录.md)。

## 开发检查与打包

仅开发工具需要 **Node.js 20 或更新版本**，无需安装依赖。在项目根目录执行：

```powershell
npm.cmd run check
npm.cmd test
npm.cmd run package
```

- `check`：检查 JavaScript 语法、本地模块与页面资源、HTML ID 和标签引用、版本号及扩展权限。浏览器交互行为需另行实际验证。
- `test`：使用 Node.js 内置测试验证完整响应、重试与取消、业务输入输出、事实与店铺隔离、读取去重和任务接续；测试使用模拟请求，不消耗 API 额度。
- `package`：在 Windows 下将扩展文件和根目录安装说明打包到 `releases/autoreply-edge-frontend-v0.4.1.zip`，文件名随插件版本号变化。

`releases` 为本地生成目录，`output` 用于本地界面截图与验收记录，均不随源码提交。

两个测试文件分别维护请求控制和评价业务的关键回归，不参与扩展运行或打包。整理代码时优先删除临时诊断脚本和重复用例，保留对暂停、重试、迟到结果及跨店铺隔离的检查。

## 权限

扩展申请 `sidePanel`、`storage`、`alarms`、`tabs`、`scripting`，以及 HTTP/HTTPS 网站访问权限，用于侧边栏、本机保存、任务唤醒、固定来源校验和网页浮标。

侧边栏中的前端模拟不需要服务器或 API Key；真实生成需要在设置中提供 Key。读取脚本只注入绑定评价页，其他网页只接收浮标摘要。真实业务接入范围和后续待确认事项见 [产品定位](PRODUCT_POSITIONING.md)。
